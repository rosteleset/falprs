# FALPRS v1.2.0

[Русский](v1.2.0.ru.md)

## Highlights

- The build and update scripts now install the Rust implementation of FALPRS, replacing an existing C++ installation. The service runs on x86-64 and uses AVX2 and FMA when available.
- Video streams share a bounded number of recognition pipelines. Face and vehicle inference for the same frame can run concurrently.
- License plate recognition uses UrbanOmniDetect-2 for vehicle footprint detection. Deleting an LPRS stream now marks it as deleted in the database, as in FRS.
- FALPRS can pass inference inputs to a local Triton container through system shared memory. It falls back to gRPC when shared memory is unavailable. Inference responses larger than 4 MB are supported again.
- Camera connections support cameras that offer only Basic authentication. Face search counts duplicate event records once.
- The API validates stream and common configuration values. It drops unknown keys and treats `null` as removal in configuration updates. `motionDetection` returns HTTP 400 for an invalid start time or duration.

## Upgrading from v1.1.6

1. Back up the project databases. If your installation predates the `.env` file, set `TRITON_VERSION` to the container version you currently use.
2. Check out `v1.2.0` and run `sudo ./scripts/update_falprs.sh` from the checkout. The updater migrates `config.yaml` to `config.toml`, keeps `config.yaml.bak`, and switches the service unit to TOML. It reports customized settings that it drops. Review any migration warnings.
3. The updater also converts stored Triton addresses on HTTP port 8000 to gRPC port 8001 and cleans stored configurations. When cleanup changes database rows, it saves their original configurations in `config-cleanup-<date>.json` in the FALPRS working directory.
4. To enable shared memory with a Triton container created by an older script, recreate it once with `sudo ./scripts/triton_recreate.sh`. FALPRS can continue to use gRPC until shared memory is available.

For a phased rollout, run `--build`, `--install`, and `--finish` as separate invocations of the update script. Take the node out of service before `--install`. When upgrading from C++, take the old nodes out of service before `--finish` changes the shared database, since they cannot use the migrated gRPC port.
