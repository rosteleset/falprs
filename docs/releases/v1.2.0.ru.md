# FALPRS v1.2.0

[English](v1.2.0.md)

## Основные изменения

- Скрипты сборки и обновления устанавливают реализацию FALPRS на Rust, заменяя установленную реализацию на C++. Сервис работает на x86-64 и использует AVX2 и FMA при их наличии.
- Видеопотоки делят ограниченное число конвейеров распознавания. Распознавание лиц и автомобилей в одном кадре может выполняться параллельно.
- LPRS использует UrbanOmniDetect-2 для определения контура автомобиля. При удалении видеопотока LPRS он теперь помечается в базе как удалённый, как и в FRS.
- FALPRS может передавать входные данные моделей локальному контейнеру Triton через системную разделяемую память. Если она недоступна, сервис использует gRPC. Восстановлена поддержка ответов Triton размером более 4 МБ.
- Поддерживаются камеры, предлагающие только Basic-аутентификацию. Поиск лиц учитывает повторяющиеся записи событий один раз.
- API проверяет значения в настройках видеопотоков и общих настройках. При обновлении настроек неизвестные ключи отбрасываются, а `null` удаляет значение. `motionDetection` возвращает HTTP 400 при неверном времени начала или длительности.

## Обновление с v1.1.6

1. Сделайте резервную копию баз данных проекта. Если в вашей установке ещё не использовался файл `.env`, укажите в `TRITON_VERSION` текущую рабочую версию контейнера.
2. Переключитесь на тег `v1.2.0` и запустите `sudo ./scripts/update_falprs.sh` из каталога репозитория. Скрипт преобразует `config.yaml` в `config.toml`, сохраняет `config.yaml.bak` и переводит службу на TOML. Если скрипт удалит настройки, значения которых вы меняли, он перечислит их в предупреждении. Проверьте предупреждения после обновления.
3. Скрипт также заменит HTTP-порт Triton 8000 на gRPC-порт 8001 в сохранённых настройках и очистит настройки в БД. Если очистка изменит строки в БД, исходные настройки этих строк сохранятся в файле `config-cleanup-<date>.json` в рабочем каталоге FALPRS.
4. Чтобы включить разделяемую память для контейнера Triton, созданного старым скриптом, один раз пересоздайте его командой `sudo ./scripts/triton_recreate.sh`. Пока разделяемая память недоступна, FALPRS может продолжать использовать gRPC.

Для поэтапного обновления запустите скрипт отдельно с `--build`, `--install` и `--finish`. Выведите узел из обслуживания перед `--install`. При переходе с C++ выведите старые узлы из обслуживания до того, как `--finish` изменит общую БД. Эти узлы не смогут использовать порт gRPC после миграции.
